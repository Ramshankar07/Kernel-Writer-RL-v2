Can reinforcement learning teach a small model to write faster GPU kernels?

An LLM agent writes a Triton kernel, a real GPU checks and times it, and the result is the reward. This project re-ran that loop end to end, trained it with GRPO, then audited the verifier and tried supervised fine-tuning first. The results are mixed, and this site reports them as they are.

Research write-up · Qwen2.5-Coder-7B-Instruct · Triton · Modal

GRPO stalled: most of its learning signal came from all-fail groups and benchmark timing noise. After fixing the verifier, SFT on verified kernels made the model noticeably more correct, but not faster.

What this does and does not show. SFT improved correctness on a held-out set and on KernelBench, which the GRPO runs never did. It did not produce speedups, and GRPO was not resumed on top of SFT (budget), so whether RL can add speed from this starting point is still open.

How the project unfolded

  1. Apr 2026

    Original design

    GRPO on SkyPilot + verl: the agent writes a full Triton kernel.py, AutoKernel's bench checks correctness and times it against PyTorch, and the reward is the log speedup. KernelBench was the first test set. All original results were lost with an old disk.

  2. Sept 2026

    Re-run on Modal

    Rebuilt every stage on Modal. Harness checks found real bugs: only 55 of 100 KernelBench L1 problems were harness-valid, and only 3 of 9 AutoKernel starter kernels passed the full bench.

  3. Sept 2026

    GRPO v1 and v2

    v1 (original reward, 18 steps) and v2 (dense correctness credit plus a noise floor, 10 steps). Reward barely moved, the pass rate stayed flat, and no kernel type that failed at the start was ever solved.

  4. Late Sept 2026

    Verifier fixes

    Fixed bench and KernelBench harnesses (now 100 of 100 valid). Re-measuring GRPO's best RMSNorm kernel showed its speedup was already in the starter, and its fp16 edit was a reward hack the old verifier could not see.

  5. Oct 2026

    SFT Phase 0: clean baseline

    Following an SFT-before-RL plan (drafted Sept 30), fixed the broken starters and the prompt protocol, built a 62-problem validation set, and measured the base model: pass@1 0.383.

  6. Oct 2026

    SFT Phase 1: verified data

    Ingested Dr.Kernel, KernelBook and in-repo kernels, ran every candidate through the GPU verifier and decontaminated against KernelBench: 3,022 train / 60 dev examples, 453 of them multi-turn repairs.

  7. Oct 2026

    SFT Phase 2: LoRA fine-tune

    LoRA SFT of Qwen2.5-Coder-7B-Instruct on the verified mix, with a pilot-resumable trainer on Modal.

  8. Oct 7, 2026

    SFT Phase 3: evaluation

    Validation pass@1 0.383 → 0.508; KernelBench Triton PASS 0% → 20%; no speedup. All three gates for resuming GRPO passed, but GRPO was not resumed (budget).
