Reproduce

Everything measured in this project was run on Modal from modal_app/. The results are in results/ and the slides are in presentation/. This page lists every command in the order it was run, the gotchas we hit, what the runs cost, and which file holds which number. The commands come from the docstrings of the modal_app/ modules, and every modal run file.py::fn entrypoint named here exists in the code.

GPU jobs cost real money. Before you launch anything, check what you have already spent with modal.billing.workspace_billing_report. Run one GPU stage at a time. Steps marked CPU run locally and are free.

Prerequisites

  • A Modal account with the CLI logged in (pip install modal, then modal setup).
  • A Modal secret named huggingface-secret that holds your Hugging Face token. The policy (policy.py), GRPO trainer (train_grpo.py) and SFT trainer (sft_train_modal.py) mount it to download Qwen2.5-Coder-7B-Instruct.
  • Python 3.11. All container images use debian_slim(python_version="3.11"); use the same version locally. The CPU-only scripts import huggingface_hub, pandas, pyarrow, matplotlib and transformers<5 + tokenizers (tokenizer files only, for sft_assemble.py).
  • Node.js, for the decks only: cd presentation && npm install (installs pptxgenjs).
  • Concurrency cap. The account we used allows at most 10 concurrent GPUs/containers. Each app sets its own max_containers so that one stage fits under that cap:
    • v1 bench pools: BENCH_MAX_CONTAINERS = 8 in modal_app/common.py. An agent eval uses 1 policy GPU + up to 8 bench GPUs = 9.
    • bench v2: BENCH_V2_MAX_CONTAINERS env var (default 4). Val bench: VAL_BENCH_MAX_CONTAINERS (default 6). kb v2 and SFT verification: 4 (hard-coded).
    • GRPO: 1 trainer H100 + 1 policy H100 + up to 8 bench L4s.
    If your account has a lower limit, lower these values before you run anything. 
pip install modal huggingface_hub pandas pyarrow matplotlib "transformers<5" tokenizers
modal setup
modal secret create huggingface-secret HF_TOKEN=hf_xxx

Persistent state: Volume autokernel-rlvr (HF cache, GRPO/SFT checkpoints, metrics) and Dict autokernel-bench-cache (v1 bench result cache). Both are created on first use.

modal deploy bench_v2_modal.py        # autokernel-bench-v2

Stage 3: GRPO via spawn

Gotchas

Each of these cost us a run.

  • Upstream bench.py takes --kernel, not --kernel-type. It prints its metrics to stdout and writes no results.tsv. bench_modal.py:parse_stdout parses the stdout.
  • --quick skips the numerical-stability checks. The rmsnorm and flash_attention starters PASS quick but FAIL full, so the reward uses the full bench.
  • AutoKernel's KernelBench starter keeps super(Model, self) after the class is renamed to ModelNew, so every starter crashes. The identity test uses class ModelNew(Model): pass instead.
  • AutoKernel's upstream bench_kb.py (not vendored here) times the CPU get_inputs() inside a 30 s trial timeout. KB containers need cpu=8, memory=32768, and even then 9 problems with huge inputs time out intermittently. kb v2 fixes this.
  • bench_kb.py never seeds weight init, so all 35 conv problems fail even for an identical model. Under v1 only 55/100 Level 1 problems are valid (results/kb_valid_problems.json). kb v2 makes all 100 valid (results/v3/kb_v2_valid_problems.json).
  • The kb_cache dir holds both N.py and N.json, so list only the .py files. An early run read problems 1–50 twice. Both runs are kept as kb_sanity_1_50_run{1,2}.jsonl for repeatability.
  • Use spawn for long jobs. A modal run --detach GRPO job was cancelled at step 5.
  • KernelBook get_init_inputs() returns [args, kwargs] (paritybench style) and imports _paritybench_helpers.
  • The SFT verifier runs its batches serially inside each container. Use a small --batch for slow autokernel-format rows.
  • zsh doesn't word-split $var in loops. Wrap shell loops in bash -c.
  • Modal has no MI300X, so the AMD path (reward_amd.py, worker_amd.py under src/autokernel-rlvr/) is design-only.

Data and licenses

  • The SFT datasets are not published. results/v3/sft/*.jsonl (candidates, verified rows, sft_train.jsonl, sft_dev.jsonl) is gitignored. To regenerate it, run the Phase 1 pipeline: modal_app/sft_ingest_*.py → sft_select.py → sft_verify_modal.py → sft_decontam.py → sft_assemble.py. The summaries and mix_report are committed so you can check your rebuild against ours.
  • KernelBook (GPUMODE/KernelBook): MIT at the pinned revision 1576375bc92745b490e1cdf2fce01eba76d9f847 (dataset_permissive.parquet). Targets are TorchInductor output. Per-row upstream repo licenses are kept in meta.
  • Dr. Kernel (hkust-nlp/drkernel-coldstart-8k @ cba0ef06a5b1e3c307b7acfa8b6acb7a46578105): tagged MIT on Hugging Face, but its paper says the trajectories were distilled from GPT-5, so OpenAI's output terms (no use to develop competing models) may apply. We treat it as research use only until cleared.
  • In-repo data: kernels written by our own Qwen2.5-Coder-7B-Instruct policy during the GRPO and agent-eval rollouts, re-verified with bench v2. No third-party data.
  • Vendored AutoKernel code in results/autokernel_src/: MIT (results/autokernel_src/LICENSE).
  • This project: Apache-2.0 (LICENSE).
  • Excluded by choice: ppbhatt500/kernelbook-triton-reasoning-traces (KernelBench-derived) and siro1/*. KernelBench L1 and the val set are never used for training.
